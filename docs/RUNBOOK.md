# Что делать, когда сайт сообщает о проблеме

Сайт наблюдает за собой сам и пишет в Telegram. Здесь — что означает каждое
сообщение и что с ним делать. Ничего из этого не срочно настолько, чтобы
чинить ночью: работа продолжает показывать последнее, что у неё есть.

## Два адреса

| | |
|---|---|
| **работа** | https://nikolaigrigoriev.com — ветка `main` |
| **репетиция** | https://nikolaigrigoriev-staging.onrender.com — ветка `staging`, вход по паролю |

Порядок изменения: правка → `staging` → посмотреть глазами → слить в `main`.
Репетиция намеренно слепая: у неё нет ключей кольца (иначе она отобрала бы
авторизацию у работы) и нет Telegram (иначе всё приходило бы дважды). Она
показывает вшитую запись и говорит `live: false` — это её нормальное состояние.

## Сообщения и что они значат

**🔴 Сайт не отвечает** — упал сервер или домен. Проверить панель Render. Если
сайт вернулся сам, придёт «🟢 снова работает» со временем простоя. Одиночное
сообщение сразу после деплоя — не поломка: с диском Render останавливает старый
экземпляр перед запуском нового, наблюдатель даёт вторую попытку через минуту.

**🔴 Проверка законов работы не прошла** — изменилось то, что меняться не
должно: заморозка прошлого, кривая тишины, семя дня, герметичность записи.
Ничего не выкатывать, пока не понято. Запустить у себя: `npm test`.

**🔴 Обновление не прошло проверку и откачено** — новая версия поднялась, но
сайт после неё повёл себя не так, и вернулась предыдущая. Сайт цел. Смотреть
лог указанного прогона: там написано, что именно не сошлось.

**🔴 Сайт показывает не то, что должен** — регулярная проверка глазами зрителя
(дважды в день) нашла расхождение: страница не отвечает, картины не появились,
подпись противоречит записи, работа показывает не последний записанный день.

**🟡 Сегодняшний день не дошёл до сайта** — свежая картина не нарисована, не
выложена или не отдаётся. Работа покажет вчерашнее. Перезапустить вручную:
Actions → `daily-state` → Run workflow.

**🔴 Слетела авторизация Oura** — обновить `OURA_TOKEN` в Render → Environment.
Пока он не обновлён, сайт честно показывает сохранённую запись и **не** рисует
это как молчание тела.

**🟡 Кольцо не отдаёт данные N дней** — не поломка сайта. Открыть приложение
Oura и дать кольцу синхронизироваться. Работа тем временем выцветает — так и
задумано.

**🟡 Oura отдал не все данные** — обычно чинится само к следующему синку.

## Если нужно вмешаться руками

Понадобится `RENDER_TOKEN` (лежит в `~/.zshrc`) и
`SRV=srv-d7ektha8qa3s73ddeqd0`.

Выложить текущий `main`:

```bash
curl -sX POST -H "Authorization: Bearer $RENDER_TOKEN" \
  https://api.render.com/v1/services/$SRV/deploys -d '{}'
```

Вернуть предыдущую версию (быстро — сборка уже есть):

```bash
curl -sX POST -H "Authorization: Bearer $RENDER_TOKEN" \
  -H "Content-Type: application/json" \
  https://api.render.com/v1/services/$SRV/rollback -d '{"deployId":"dep-…"}'
```

Список последних версий, чтобы взять `deployId`:

```bash
curl -s -H "Authorization: Bearer $RENDER_TOKEN" \
  "https://api.render.com/v1/services/$SRV/deploys?limit=10"
```

Пройти по сайту как зритель, у себя:

```bash
node scripts/smoke.js https://nikolaigrigoriev.com
```

## Где что лежит

**Запись тела** — на постоянном диске Render (`/var/record`), переживает
деплой. Копия каждую ночь уезжает на домашний сервер в закрытый дата-рум
(`/srv/dataroom/state/record`, таймер `record-backup.timer`).

**Картины** не хранятся. Они выводятся из правила и записи. Хранится только
одна картинка на работу — как она стоит сегодня (`state/*.webp`, ~250 КБ на
все три), она переписывается каждое утро. Всё остальное рисует движок работы в
браузере: полсекунды на день после прогрева.

**Тишина** не запечена в файл. В картинке лежит последний записанный день без
выцветания, а браузер сводит цвет и растворяет картину по сегодняшнему разрыву.
Поэтому выцветание не может устареть — раньше могло, и сайт две недели показывал
старое состояние с подписью «Today».

## Чего делать нельзя

- Копировать ключи `OURA_*` на репетицию: refresh-токен ротируется, две копии
  отберут авторизацию друг у друга, и работа ослепнет.
- Копировать `TG_*` на репетицию: тревоги пойдут дважды.
- Удалять файлы в `89/record/` — это write-once архив кадров, часть работы.
- Чинить «медленно» хранением картинок: измеряли — медленным был запуск движка
  (8.7 с на телефоне), а не рисование (0.5 с).
