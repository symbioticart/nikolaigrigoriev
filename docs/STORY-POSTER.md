# Постер 89 — кадр дня и плёнка недели в телеграм

Что делает: каждое утро отправляет в телеграм кадр «Вариации 89» за этот день,
а вечером последнего дня недели — плёнку из семи кадров. Оба раза — так, чтобы
файл доехал **нетронутым** и его можно было сразу поставить в сторис.

Код: `scripts/story-poster.js`. Живёт на домашнем сервере (ootrohome), не на
Render: сайт занят раздачей работы, а не почтой.

## Почему картинка была мыльной

Дело не в разрешении. Кадр в архиве и так ровно тот, что нужен сторис —
1080×1920 PNG, снятый прямо с холста страницы.

Портил его транспорт:

- **`sendPhoto` пережимает.** Телеграм перекодирует всё, что приходит этим
  методом, в JPEG и уменьшает. Никакое улучшение источника этого не переживёт.
- **GIF — это 256 цветов**, и телеграм всё равно перегоняет его в MP4. На
  масляных градиентах это видно сразу: полосы вместо переходов.

Лечится не рендером, а методом отправки:

| | было | стало |
|---|---|---|
| день | `sendPhoto` (JPEG, уменьшено) | `sendDocument` — PNG 1080×1920 побайтово |
| неделя | `sendAnimation` с GIF | `sendDocument` — H.264 MP4 1080×1920, 30 fps |

`sendDocument` хранит файл как есть — это единственный метод телеграма,
который ничего не трогает.

Рядом с документом уходит сжатая копия (`sendPhoto` / `sendVideo`) — только
затем, чтобы работу было видно в ленте, не открывая файл. Выключается
`STORY_PREVIEW=0`.

## Запуск

    node scripts/story-poster.js daily              # кадр сегодняшнего дня
    node scripts/story-poster.js weekly             # плёнка за 7 дней
    node scripts/story-poster.js daily 2026-09-01   # любой день из архива
    node scripts/story-poster.js weekly 2026-09-01  # неделя, кончающаяся этим днём

Ноль зависимостей — как и весь репозиторий. Для плёнки нужен `ffmpeg`; если
его нет, неделя уходит семью отдельными кадрами, каждый полного размера.

## Окружение

| | |
|---|---|
| `TG_BOT_TOKEN` | обязателен |
| `TG_CHAT_ID` | обязателен |
| `STORY_RECORD_DIR` | локальная копия `89/record` — быстрее и без сети |
| `SITE` | откуда брать кадр, если локальной копии нет (по умолчанию `https://nikolaigrigoriev.com`) |
| `STORY_PREVIEW=0` | не слать сжатую копию для превью |
| `STORY_DAYS` | сколько дней в плёнке (по умолчанию 7) |
| `STORY_FRAME_SECONDS` | сколько держать кадр (по умолчанию 2 → неделя = 14 с) |
| `STORY_FFMPEG` | путь к ffmpeg, если он не в `PATH` |

Кадр берётся сначала из `STORY_RECORD_DIR`, потом с сайта
(`$SITE/89/record/<дата>.png` — сервер раздаёт этот путь). Архив write-once:
чего за день нет, того нет — это молчание, а не поломка, и плёнка просто
собирается из того, что есть.

## Таймеры

`scripts/systemd/` — четыре юнита, копировать в `/etc/systemd/system/`:

    sudo cp scripts/systemd/story-poster-*.{service,timer} /etc/systemd/system/
    sudo systemctl daemon-reload
    sudo systemctl enable --now story-poster-daily.timer story-poster-weekly.timer

Токен лежит в `/etc/v89-poster.env` (режим `600`), не в репозитории:

    TG_BOT_TOKEN=...
    TG_CHAT_ID=...
    STORY_RECORD_DIR=/srv/nikolaigrigoriev/89/record

Утренний таймер стоит на 11:30: `daily-89` снимает кадр в 08:00 UTC, а
планировщик GitHub опаздывает на 26–218 минут, так что часа запаса мало не бывает.

## Про сторис

Документ приходит в телеграм как файл — сохранить в галерею, оттуда в сторис.
Оба формата уже в нужном соотношении 9:16, кадрировать нечего.

Плёнка — 14 секунд (7 кадров по 2), в один сегмент сторис влезает целиком.
`yuv420p` и чётные стороны стоят намеренно: без них инстаграм и половина
плееров файл не откроют.
