# Как добавить работу

Работа состоит из двух вещей: **правила**, по которому день становится
картиной, и **описания** — кто она такая. Всё остальное сайт делает сам.

## 1. Правило

`art/<id>/painter.js` — один файл, который выставляет наружу функцию рисования:

```js
window.<Имя>Painter = { paintDay(p, day, DATA, w, h) { … } };
```

Требования жанра, не переговорные:

- **Один день — одна картина.** Никакого `Math.random`: всё случайное растёт из
  семени дня. Один и тот же день обязан дать один и тот же холст всегда.
- **День взвешивается только против предыдущих.** Причинные перцентили, как в
  `rule.js`. Иначе прошлое будет переписываться, когда запись растёт.
- **Ни один показатель не читается обратно.** Каждая видимая черта складывается
  минимум из двух сигналов.
- **Тишина не трогает форму.** Она либо ложится поверх готовой картины (`over`),
  либо гаснет внутри мазка (`within`) — но никогда не двигает мазки.

Проверить на крайних днях до всего остального: лучший `2023-03-12`, худший
`2023-10-04`. Если они не отличаются заметно — отображение декоративно.

## 2. Описание

Одна запись в `works.json`:

```json
"<id>": {
  "title": "…",
  "listed": false,              // сначала невидимо: работа обкатывается вживую
  "selected": false,            // на главную — потом, осознанно
  "medium": "…",                // подпись, какую напечатал бы музей
  "canvas":  { "w": 900, "h": 1200, "density": 1 },
  "ground":  "#eee9dd",         // цвет, в который работа растворяется
  "silence": "over",            // over | within
  "engine":  { "painter": "<id>/painter.js", "data": "/<id>/data.json", "dateField": "day" },
  "state":   { "w": 900, "h": 1200, "quality": 0.88 },
  "rule":    { "seed": "…", "foot": "…" }
}
```

`ratio` не пишется: форма работы — это её холст, `w / h`.

## 3. Запись

Если работа читает уже существующую запись (дни или ночи) — ничего не нужно.
Если ей нужна своя — добавить отдачу в `server.js` рядом с существующими и
включить работу в `/state/meta.json`.

## 4. Тексты — через совет

**Прежде чем работа станет видимой**, тексты проходят совет по современному
искусству (`areopagus`): название, `medium`, семь-двенадцать законов правила,
подпись. Регистр — как у остальных: точный факт, ноль объяснений смысла, без
слов «loading», «real-time», «beautiful». Русская проза — чистым инфостилем.

Прогнать всё написанное через `humanize-text`.

Правила работ расходятся ровно в одном законе — седьмом, о семени дня. Если
новая работа расходится ещё в чём-то, это стоит обсудить: скорее всего, это
другая работа, а не другая вариация.

## 5. Показать

1. Ветка `staging`, пуш → конвейер выложит на репетицию и пройдёт по ней.
2. Посмотреть глазами: `https://nikolaigrigoriev-staging.onrender.com`.
3. Проверить крайние дни и день тишины.
4. Слить в `main` → конвейер выложит на сайт и проверит; если что-то не так,
   вернёт предыдущую версию.
5. Утренний рисовальщик сам нарисует картинку состояния новой работы.
6. Когда работа обкатана: `listed: true`, и отдельным решением `selected: true`.

## Что проверяется само

`npm test` не даст:

- назвать художника, которого нет (именно так третья работа однажды поднялась
  без единой своей картинки);
- оставить работу без правила, грунта, холста или размера;
- вывести на главную работу, помеченную как невидимая.

А прогулка зрителя (`scripts/smoke.js`) проверит, что новая работа показывает
последний записанный день и что её страницы отвечают.
